# 猎聘自动投递功能

## 前置条件

1. 用户已上传简历（通过 `getResume` 工具确认状态至少为 ANALYZED）
2. Liepin MCP Server 已启动且浏览器已登录猎聘（通过 `liepin_login_check` 确认）
3. 用户明确指定了投递的岗位和城市

## 能力范围

| 操作 | MCP 工具 | 说明 |
|------|----------|------|
| 检查登录 | `liepin_login_check` | 检查猎聘登录状态，未登录则打开浏览器供扫码 |
| 搜索岗位 | `liepin_search_jobs` | 按关键词、城市、薪资搜索 |
| 查看详情 | `liepin_get_job_detail` | 获取岗位JD和任职要求 |
| 单个投递 | `liepin_apply_job` | 打开岗位链接（进入IM聊天页）→ 点击顶部「简历投递」 |
| 批量投递 | `liepin_batch_apply` | 搜索 + 逐个进入聊天页点击「简历投递」（推荐） |
| 查看简历 | `getResume` (ResumeTool) | 获取用户简历文本，供投递时作为 resumeText |

## 执行流程

### ⚠️ 核心规则（最高优先级）
- **keyword 必须严格使用用户原话中的岗位名称**：用户说"销售"就用"销售"，用户说"产品经理"就用"产品经理"
- **绝对禁止**根据简历内容、用户背景、历史对话自行推断或修改关键词
- 即使用户的简历全是技术栈，只要用户说的是"销售"，就必须搜"销售"（用户可能想转行）
- **禁止在确认关键词前调用 getResume**：简历内容会干扰你的判断，先确认投递意向再获取简历

### Step 1：确认投递意向
- 收集用户目标：岗位（keyword）、城市（city）、数量（默认5个）
- 如有未明确的参数，逐一询问用户
- **不要自行修改用户说的岗位名称**
- **此步骤不要调用 getResume，等用户确认后再获取**

### Step 2：检查前置条件
- 调用 `liepin_login_check` → 确认猎聘已登录
  - 如果未登录：告知用户需要在弹出的浏览器中扫码登录猎聘
- ⚠️ 猎聘使用平台自有简历（用户在猎聘已编辑好的简历），不需要获取数据库简历

### Step 3：搜索与确认
- 调用 `liepin_search_jobs` 搜索岗位
- 向用户展示搜索结果（岗位名、公司、薪资、地点）
- 询问用户要投递哪些（"前3个"、"全部"、"第1和第4个"等）

### Step 4：投递（点击「发简历」按钮）
- 用户确认后调用 `liepin_batch_apply`，传入：
  - `keyword`: 岗位关键词（严格使用用户原话）
  - `city`: 城市
  - `maxCount`: 投递数量
- **投递原理**：猎聘使用用户在平台上已编辑好的简历，点击聊天页顶部「发简历」按钮即可发送，无需传简历文本
- 工具会自动处理：岗位详情页 → 点击「立即沟通」→ 聊天页 → 点击「发简历」
- 逐一报告投递进度

### Step 5：汇总
- 投递完成后汇总结果：成功/失败/跳过数量
- 记录到数据库供后续查询

## 限制与注意事项

1. **投递方式**：猎聘点击岗位后直接进入IM聊天页，顶部有「简历投递」按钮。点击即发送简历，之后等待招聘顾问回复
2. **猎聘风控**：短时间内大量投递可能触发验证码或IP封禁，MCP Server 内置 2-5 秒随机延迟
3. **登录过期**：猎聘 cookie 可能过期，投递前务必先调用 `liepin_login_check`
4. **岗位时效**：搜索结果可能包含已下架岗位，投递失败时会自动跳过
5. **简历匹配**：投递前建议先让 AI 分析岗位JD和用户简历的匹配度

## 使用示例

| 用户说 | Agent 行为 |
|--------|-----------|
| "帮我在猎聘投5个销售岗位，杭州" | 检查登录→获取简历→搜索→确认→批量「立即沟通」投递 |
| "先看看杭州有什么销售岗位" | 调用 `liepin_search_jobs` 展示，不投递 |
| "帮我把简历投到之前看到的第1、3个岗位" | 调用 `liepin_apply_job` 逐个投递（立即沟通方式） |
| "今天投了几个了" | 查询数据库投递记录展示 |
| "猎聘登录了吗" | 调用 `liepin_login_check` |
